\begin{abstract}
Standard autoregressive large language model (LLM) inference processes every
transformer layer for every generated token, producing per-token latencies
that are highly variable and potentially unbounded under growing context.
In latency-sensitive applications such as clinical decision support, this
tail behaviour violates hard Service-Level Objective (SLO) deadlines.
We present an anytime algorithm framework for LLM token generation that
exploits the predictive signal available at intermediate transformer layers
to make deadline-aware routing decisions at the application level.
Three routers are implemented on TinyLlama-1.1B-Chat on a bare-metal
NVIDIA RTX~6000~Ada GPU (50.9~GB VRAM, CUDA~12.4):
(i)~a \emph{stateless two-pass} router (threshold decay, no KV cache);
(ii)~a \emph{KV-cached single-pass} router using a post-hoc forward hook
     that captures Layer-16 activations during the single 22-layer pass,
     eliminating KV-cache desynchronization; and
(iii)~an \emph{async-overlap} variant that pipelines CPU tokenization with
      GPU inference via CUDA streams and pinned memory.
A heterogeneous pipeline decomposition reveals that GPU compute accounts
for 99.3\% of per-token latency ($T_{\text{gpu}}$~=~15.57~ms mean),
with PCIe transfer (0.023~ms) and CPU preprocessing (0.091~ms) negligible,
validating the application-level routing abstraction.
At the hard deadline $D=30$~ms, the KV-cached router achieves
P99~TPOT~=~17.84~ms (SLO compliance ratio $R = 0.595$) with 0\%
deadline misses across 240 token samples.
The async-overlap router reduces this to P99~=~17.41~ms ($R=0.580$).
The stateless router's P99~=~30.27~ms exceeds the 30~ms deadline ($R=1.009$),
demonstrating that two-pass inference is not schedulable at this deadline.
An exit-layer ablation (L5, L11, L16, L20) confirms Layer~16 as the earliest layer
with substantial predictive signal (32\% oracle agreement, 64.7\% when
high-confidence).
A 30-query PubMedQA clinical benchmark achieves 0\% deadline misses
at 68.24~tok/s throughput and 71.4\% answer accuracy.
Gumbel EVT bounds establish $P(\text{TPOT}>30\,\text{ms})<10^{-6}$
for sequences up to 512~tokens.
Thermal profiling over 500 consecutive tokens confirms WCET stability,
validating the static routing table.
\end{abstract}

\section{Introduction}
% ─────────────────────────────────────────────────────────────────────────────

Large language models (LLMs) have become foundational components in
latency-critical applications: clinical decision support~\cite{singhal2023large},
interactive human-computer interfaces~\cite{ouyang2022training}, and
autonomous vehicle reasoning~\cite{wen2023dilu}.
In all such contexts, the system must commit a token (or produce an
answer) before a hard deadline.
Standard autoregressive decoding executes all transformer layers for
every token, producing execution times that are highly variable and
grow with context length.

This mismatch between standard inference and hard deadline requirements
is the central problem we address.
We adopt the \emph{anytime algorithm} paradigm~\cite{boddy1994deliberation,
zilberstein1996using}: a computation that can be safely interrupted at
any point and returns a valid (if approximate) result.
For transformer inference, the natural interruption point is at an
intermediate layer.
A confidence signal derived from that layer's logits allows the router
to decide, after the full pass completes, whether the intermediate
output is sufficient for commitment.

Our system operates entirely in user space.
The router makes application-level decisions (which logits to commit)
and does not preempt OS threads or control GPU hardware scheduling.
The GPU runs a contiguous 22-layer forward pass every token; the router
only selects which of the two available logit vectors to commit.
The relevant metric is therefore SLO compliance: whether
$\text{P99\_TPOT} \leq D$ across the inference workload.

\subsection{Contributions}

\begin{enumerate}[leftmargin=*]
\item \textbf{Post-hoc forward-hook router (KV-cached):}
      A single-pass design using \texttt{register\_forward\_hook} on
      Layer~15 (0-indexed) captures the Layer-16 hidden state during the
      contiguous 22-layer pass. Both logit vectors are available in VRAM
      after one pass; the routing decision is post-hoc, requiring no
      second forward call and preserving KV-cache consistency for all layers.

\item \textbf{Async-overlap router:}
      CPU tokenization and H2D PCIe transfer are overlapped with GPU
      inference from the preceding token using CUDA streams and pinned
      memory, demonstrating a non-blocking pipeline architecture.

\item \textbf{Heterogeneous pipeline model:}
      Per-component latency decomposition $T_{\text{total}} =
      T_{\text{cpu}} + T_{\text{pcie}} + T_{\text{gpu}} + T_{\text{sync}}$
      directly motivates the application-level routing abstraction.

\item \textbf{SLO compliance proof:}
      Empirical demonstration that $\text{P99\_TPOT} = 17.84$~ms
      at $D=30$~ms ($R=0.595$) with 0\% deadline misses across
      240 token samples on clinical prompts.

\item \textbf{Exit-layer ablation (L5--L20):}
      Systematic comparison against the full-pass oracle validates
      Layer~16 as the earliest layer with meaningful predictive signal.

\item \textbf{EVT probabilistic WCET bounds:}
      Gumbel EVT fits to 500 samples per cell establish
      $P(\text{TPOT}>30\,\text{ms})<10^{-6}$ for sequences $\leq 512$
      tokens, providing a statistically certified timing guarantee.
\end{enumerate}

\section{Background and Related Work}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Anytime Algorithms}

Anytime algorithms~\cite{zilberstein1996using,boddy1994deliberation}
produce valid results at any interruption point, with quality
improving monotonically over time.
The scheduler monitors elapsed time and commits the best available
result when the deadline approaches.
This property is essential for hard deadline systems where a slightly
lower-quality answer is always preferable to no answer.

\subsection{Early Exit in Transformer Models}

Early exit in deep networks was introduced by
Teerapittayanon et al.~\cite{teerapittayanon2016branchynet} and
adapted to transformers in FastBERT~\cite{liu2020fastbert} and
DeeBERT~\cite{xin2020deebert}, where confidence-triggered intermediate
exits reduce mean inference cost.
Schuster et al.~\cite{schuster2022confident} proposed confident
adaptive language modeling for decoder-only models.
LayerSkip~\cite{elhoushi2024layerskip} demonstrated that later layers
of TinyLlama carry substantially more predictive signal than early ones,
consistent with our ablation results.

\subsection{Real-Time Scheduling for ML Inference}

Real-time scheduling of neural network inference has been studied in
embedded settings by Bateni and Liu~\cite{bateni2020neuos} and
Xiang et al.~\cite{xiang2019pipelined}, focusing on WCET analysis and
CPU/GPU pipeline partitioning.
Our work extends this to the decoder-only LLM setting with a
user-space routing architecture that does not require OS-level thread
preemption.

\subsection{Probabilistic WCET}

Measurement-based probabilistic timing analysis~\cite{cucu2012measurement}
fits statistical distributions to execution time samples to certify
tail latency at exceedance probabilities below $1/n$.
Bernat et al.~\cite{bernat2002wcet} established Extreme Value Theory
(EVT), particularly the Gumbel distribution, as the appropriate model
for execution time tails.
Davis and Cucu-Grosjean~\cite{davis2013quantifying} survey the field.
We apply Gumbel EVT to GPU forward-pass timing samples to derive
a statistically rigorous WCET certificate.

\subsection{KV Cache Efficiency}

PagedAttention~\cite{kwon2023efficient} and FlashAttention~\cite{dao2022flashattention,
dao2023flashattention2} are the primary techniques for reducing KV-cache
memory and recomputation cost.
We exploit PyTorch~2.4's scaled-dot-product attention (which uses
FlashAttention kernels implicitly) and rely on the $O(n_{\text{cache}})$
single-token pass to bound per-token latency independently of
accumulated context.

\section{System Architecture}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Hardware and Model}

\textbf{Hardware:}
Bare-metal NVIDIA RTX~6000~Ada Generation (50.9~GB GDDR6, CUDA~12.4,
Ada Lovelace architecture, 18{,}176 CUDA cores).
Bare-metal deployment is required for valid WCET measurements;
hypervisor-induced jitter would invalidate worst-case timing.

\smallskip\noindent\textbf{Model:}
TinyLlama\slash{}TinyLlama-1.1B-Chat-v1.0~\cite{zhang2024tinyllama}: 22
transformer decoder layers (LlamaDecoder), hidden dimension 2{,}048,
32 attention heads, vocabulary 32{,}000, \texttt{bfloat16} precision.
Chat-template formatted prompts are used throughout so that measured
latencies reflect deployment-realistic context lengths
($\approx$95--145~tokens).

\smallskip\noindent\textbf{Framework:}
PyTorch~2.4.1+cu124, HuggingFace Transformers~5.6.0.

\subsection{EarlyExitTinyLlama and the Post-Hoc Hook}

We implement \texttt{EarlyExitTinyLlama}, a wrapper that registers a
\texttt{forward\_hook} on \texttt{model.layers[15]} (0-indexed, i.e.\
Layer~16) before every \texttt{forward\_cached()} call:

\begin{algorithmic}[1]
\STATE $\text{captured} \leftarrow \{\}$
\STATE \textbf{def} $\text{hook}(\text{module}, \text{in}, \text{out})$:
\STATE \quad $\text{captured}[\texttt{"h16"}] \leftarrow \text{out}[0]$
       \COMMENT{GPU ref, no host copy}
\STATE {\small \texttt{handle} $\leftarrow$ \texttt{layer15.register\_forward\_hook(hook)}}
\STATE $\text{out} \leftarrow \texttt{base\_model}(\text{ids},\, \text{past\_kv})$
       \COMMENT{22 layers run}
\STATE $\ell_{22} \leftarrow \text{out.logits}$
\STATE $\ell_{16} \leftarrow \texttt{lm\_head}(\texttt{norm}(\text{captured}[\texttt{"h16"}]))$
\STATE \textbf{return} $\ell_{16},\, \ell_{22},\, \text{out.past\_key\_values}$
\end{algorithmic}

The hook stores only a GPU tensor reference, with no host transfer and no
synchronization.
All 22 layers execute contiguously; RMSNorm and the LM head are applied
strictly after \texttt{base\_model()} returns.
Critically, every layer writes its KV states on every token regardless
of which logit the router ultimately commits, eliminating KV-cache
desynchronization.

\subsection{Three Application-Level Routers}

\subsubsection{Stateless Two-Pass Router}

The stateless router (\texttt{generate\_stateless\_anytime}) runs Layer~16 first
as a probe, applies a linear confidence threshold decay with the remaining budget,
and re-runs all 22~layers when confidence is below threshold:
\begin{equation}
\theta_t = \theta_{\min} + (\theta_{\max} - \theta_{\min})
           \cdot \frac{r - w}{D - w}
\label{eq:decay}
\end{equation}
where $r$ is remaining budget, $w = \text{WCET}_{\text{safe}}(\text{seq\_len})$,
$\theta_{\max}=0.8$, $\theta_{\min}=0.3$.
This router is presented as a baseline; its two-pass nature makes it
not schedulable at $D=30$~ms for typical chat-template prompts
(Section~\ref{sec:comparison}).

\subsubsection{KV-Cached Single-Pass Router}

The KV-cached router (\texttt{generate\_anytime\discretionary{\_}{}{\_}with\_kv}) uses
\texttt{forward\_cached()} with a fixed post-hoc threshold $\theta_{\text{kv}}=0.55$:
\begin{algorithmic}[1]
\STATE $\ell_{16}, \ell_{22}, \text{kv}' \leftarrow
       \texttt{forward\_cached}(\text{ids},\, \text{past\_kv})$
\STATE $c \leftarrow \max(\texttt{softmax}(\ell_{16}[-1]))$
\IF{$c \geq 0.55$}
    \STATE commit $\arg\max(\ell_{16}[-1])$ \COMMENT{Early Exit (Thresh)}
\ELSE
    \STATE commit $\arg\max(\ell_{22}[-1])$ \COMMENT{Full Pass}
\ENDIF
\end{algorithmic}

No forced-exit logic is needed: the single-pass always completes
within the budget.
The post-hoc decision adds zero GPU compute overhead: both logit
vectors are already in VRAM before the routing branch executes.

\subsubsection{Async-Overlap Router}

The async-overlap router (\texttt{generate\_anytime\discretionary{\_}{}{\_}async\discretionary{\_}{}{\_}overlap})
overlaps CPU preprocessing of token $t{+}1$ with GPU inference of token $t$
using a dedicated CUDA stream and pinned (page-locked) memory:

\begin{algorithmic}[1]
\STATE \textbf{Phase~A} (CPU): write $\text{tok}_{t+1}$ to pinned buf;
       \texttt{.to("cuda", non\_blocking=True)}
\STATE $\text{stream.wait\_stream}(\text{current\_stream})$
       \COMMENT{DMA lands before GPU reads}
\STATE \textbf{Phase~B} (GPU): launch \texttt{forward\_cached}
       on inference stream (non-blocking)
\STATE \textbf{Phase~C} (CPU): overlapped decode/record of token $t$
\STATE $\text{stream.synchronize}()$
       \COMMENT{wait for GPU result}
\STATE \textbf{Phase~D}: post-hoc routing on $\ell_{16}, \ell_{22}$
\end{algorithmic}

The pipeline model (Section~\ref{sec:pipeline}) shows that
$T_{\text{cpu}} = 0.091$~ms is only 0.58\% of the token budget,
so the overlap saves $\approx$0.09~ms mean latency
(3.8\% reduction in Phase~A cost, not total).

\subsection{WCET Table and Admission Policy}

Both KV-cached routers load a per-sequence-length WCET table from
\texttt{wcet\_results.json} at startup and apply a $1.10\times$
safety margin:
\begin{equation}
\text{WCET}_{\text{safe}}(s) = 1.10 \times
    \max\bigl\{\text{WCET}_{\text{measured}}(s_i) : s_i \geq s\bigr\}
\label{eq:wcet_safe}
\end{equation}
The ceiling lookup (smallest profiled bin $\geq$ current sequence length)
ensures the bound is always conservative.
A request is admitted only if $\text{WCET}_{\text{safe}}(s) \leq D$.

\subsection{Heterogeneous Pipeline Decomposition}

latency into its physical components:
$T_{\text{total}} = T_{\text{cpu}} + T_{\text{pcie}} +
T_{\text{gpu}} + T_{\text{sync}}$.

synchronous and asynchronous pipeline models.

$T_{\text{cpu}} \ll T_{\text{gpu}}$.

\subsection{EVT Probabilistic WCET Bounds}
\label{sec:evt}

Empirical WCET ($\max \times 1.10$) over 50 runs is a single-sample
bound that provides no probabilistic guarantee below exceedance
probability $1/n = 0.02$.
Extreme Value Theory (EVT)~\cite{bernat2002wcet,coles2001introduction}
extrapolates the timing tail to exceedance probabilities far below $1/n$.

We collect 500 timing samples per (seq\_len, exit\_layer) cell and
fit a Gumbel (Type~I EVT) distribution to the upper 20\% of samples
(Peaks-Over-Threshold method).
The Gumbel CDF is
$F(t) = \exp\!\bigl(-\exp(-(t-\mu)/\sigma)\bigr)$
with parameters fitted by maximum likelihood.
The probabilistic WCET bound at exceedance probability $\varepsilon$ is
$\text{pWCET}(\varepsilon) = F^{-1}(1-\varepsilon)$.

\subsection{Admission Control}

\begin{equation}

\label{eq:admit}
\end{equation}

\subsection{Multi-Request Capacity Analysis}
\label{sec:capacity}

Under a token-level round-robin policy serving $N$ concurrent inference
requests, the effective TPOT seen by each request is $N \times C$,
where $C$ is the per-token execution time.
The system meets the SLO for all $N$ requests if $N \times C \leq D$:
\begin{equation}
N_{\max} = \left\lfloor \frac{D}{C} \right\rfloor
\end{equation}

Using the benchmark P99 TPOT $C = 15.99$~ms and $D = 30$~ms:
\begin{equation}
N_{\max} = \left\lfloor \frac{30}{15.99} \right\rfloor = 1; \quad
N{=}1: \; 1 \times 15.99 = 15.99\;\text{ms} \leq D
\end{equation}

The RTX~6000~Ada delivers production SLOs well within the 30~ms hard deadline,
validating the routing framework for latency-sensitive clinical deployments.

% ─────────────────────────────────────────────────────────────────────────────
\section{Discussion}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Why KV Caching Is Essential}

The stateless two-pass router is fundamentally limited by the need
to run the model twice per token.
For chat-template PubMedQA prompts ($\approx$150~tokens), the L16
probe consumes $\approx$10.8~ms; when confidence is below threshold
(89.3\% of tokens), the full pass adds another $\approx$14.9~ms,
for a combined mean of 24.7~ms and P99 of 30.3~ms.
The 1.3\% miss rate at $D=30$~ms is not recoverable without
eliminating the second pass.

The KV-cached design eliminates the second pass by capturing L16
activations via hook during the single contiguous forward pass.
The hook stores a GPU tensor reference (no host transfer), and the
routing decision executes strictly after the GPU returns.
This reduces mean TPOT from 24.7~ms to 15.7~ms (36\% reduction)
and clears all deadline misses.

\subsection{GPU Dominance and the Right Level of Abstraction}

The pipeline decomposition (Section~\ref{sec:pipeline}) reveals that
99.3\% of latency is GPU compute.
This has a direct implication for system design: the correct point
of control is the application-level routing decision (which logits
to commit), not OS thread priority, CPU preprocessing, or PCIe transfer.
Optimising any non-GPU component can contribute at most 0.7\% of
total latency.
The async-overlap router is architecturally sound, correctly
pipelining all non-GPU work, but the practical benefit on this
hardware is 3.8\% of the non-GPU fraction, which is 0.027\% of
total latency.

\subsection{EVT Framing and Appropriate Confidence Levels}

The pWCET analysis uses exceedance probabilities in the
$10^{-3}$--$10^{-6}$ range, which is appropriate for clinical
decision support systems~\cite{singhal2023large}.
Aviation certification (DO-178C) targets $10^{-9}$; automotive
(ISO~26262, ASIL-D) targets $10^{-8}$.
A biomedical QA system falls closer to IEC~60601-1 general medical
device requirements, where $10^{-3}$--$10^{-4}$ exceedance is the
relevant benchmark.
The empirical result ($P(\text{miss}) \ll 10^{-3}$ for seq$\leq$512)
is conservatively strong for this domain.

\subsection{Limitations and Future Work}

\textbf{Model scale:}
TinyLlama-1.1B is the smallest production-quality LLM.
Larger models (7B, 70B parameters) will have substantially higher
per-token latency; the framework scales, but the WCET table and exit
layer require re-profiling.

\textbf{Exit head quality:}
The shared LM head is applied at Layer~16 without fine-tuning.
A jointly-trained lightweight exit head (small MLP) would improve
L16 oracle agreement beyond 32\%, increasing the early-exit rate
from 5.3\% and reducing mean TPOT further.

\textbf{Multi-request batching:}
The $N_{\max}=2$ round-robin capacity is conservative.
Hardware-level batching (multiple requests processed in a single
GPU kernel) could raise this substantially but requires re-profiling
the WCET table under batch load.

\textbf{Async benefit at scale:}
The async-overlap router's 0.09~ms saving would grow with
$T_{\text{cpu}}$ (heavier preprocessing pipelines, retrieval
augmentation) or with PCIe~3.0 systems where $T_{\text{pcie}}$
is larger.

\section{Conclusion}
% ─────────────────────────────────────────────────────────────────────────────

We presented a KV-cached anytime algorithm for LLM token generation that
enforces hard SLO deadlines at the application level by design.
The core insight is that the KV-cache desynchronization problem inherent
in two-pass stateless routers is eliminated by a single
\texttt{forward\_cached()} call that captures Layer-16 intermediate
activations via a post-hoc forward hook while running all 22 transformer
layers contiguously.
The routing decision (which logit vector to commit) is made strictly
after the GPU returns, with no second forward call and no KV-state
corruption.

On a bare-metal RTX~6000~Ada GPU, the KV-cached router achieves
P99~TPOT = 17.84~ms at $D=30$~ms ($R=0.595$) with 0\% deadline misses
across 240 token samples, while the stateless two-pass router's P99 =
30.27~ms exceeds $D$ ($R=1.009$).
An async-overlap variant further reduces P99 to 17.41~ms ($R=0.580$)
by pipelining CPU preprocessing with GPU inference via CUDA streams.
A 30-query PubMedQA benchmark confirms 0\% deadline misses at
68.24~tok/s with 71.4\% accuracy.

A heterogeneous pipeline decomposition shows that GPU compute accounts
for 99.3\% of per-token latency, directly validating the
application-level routing abstraction.
EVT Gumbel fits establish $P(\text{TPOT}>45\,\text{ms})<10^{-6}$
for sequences up to 512~tokens.
Thermal profiling confirms WCET stability over 500 consecutive tokens.

These results demonstrate that predictive early-exit mechanisms,
when implemented via a post-hoc single-pass forward hook with KV-cache
consistency, can enforce hard SLO deadlines on LLM token generation
without modifying model weights, without OS-level thread preemption,
and without sacrificing output quality.
