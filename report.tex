\begin{abstract}
Standard autoregressive large language model (LLM) inference processes every transformer layer for every generated token, producing per-token latencies that are highly variable and potentially unbounded in the worst case under growing context. In latency-sensitive applications such as clinical decision support and cyber-physical systems, this tail latency violates hard real-time constraints. This paper presents an anytime algorithm framework for LLM token generation that exploits the predictive signal present in early transformer layers to make deadline-aware exit decisions. We implement two schedulers on TinyLlama-1.1B-Chat: a stateless two-pass dynamic threshold scheduler and a KV-cached single-pass scheduler using a forward hook to capture intermediate representations. Profiling on a bare-metal RTX~4000~Ada GPU (21~GB VRAM) demonstrates that the KV-cached scheduler achieves P99 TPOT of 25.2~ms against a hard deadline of $D = 45$~ms (utilization $U = 0.56$), with zero deadline misses across 240 token samples on chat-template formatted clinical prompts. In contrast, the stateless scheduler exceeds the deadline on 16\% of tokens ($P99 = 48.3$~ms, $U = 1.07$). An exit-layer ablation study across L5 through L20 validates Layer~16 as the exit point. Extreme Value Theory (EVT) Gumbel fits establish probabilistic WCET bounds: $P(\text{TPOT} > 45\,\text{ms}) < 10^{-8}$ for sequences up to 512 tokens. Thermal profiling over 500 consecutive tokens confirms WCET stability (drift $= -0.86$~ms, $-4.0\%$). Liu \& Layland analysis yields $N_{\max} = 2$ concurrent schedulable inference requests under round-robin token scheduling. A 30-query PubMedQA clinical benchmark confirms 0\% deadline misses at 51.2~tokens/s throughput.
\end{abstract}

\section{Introduction}
% ─────────────────────────────────────────────────────────────────────────────

Large language models (LLMs) have emerged as foundational components in an expanding range of time-critical applications: clinical decision support~\cite{singhal2023large}, interactive human-computer interfaces~\cite{ouyang2022training}, and autonomous vehicle natural language reasoning systems~\cite{wen2023dilu}. In all such contexts, the system is required to produce a token---or commit to an answer---before a hard deadline expires. Standard autoregressive decoding, however, executes all transformer layers for every generated token, producing execution times that are highly variable and, in the worst case, exceed any fixed deadline as context length grows.

This mismatch between standard LLM inference and hard real-time requirements is the central problem we address. We frame token generation as a collection of sporadic real-time tasks $\{\tau_i\}$, each with computation time $C$, deadline $D$, and minimum inter-arrival period $T \geq C$~\cite{buttazzo2011hard}. A scheduler is \textit{schedulable} if it guarantees $\text{P99\_TPOT} \leq D$, equivalently, utilization $U = \text{P99\_TPOT}/D < 1.0$.

Our approach is grounded in the \textit{anytime algorithm} paradigm~\cite{boddy1994deliberation,zilberstein1996using}: a computation that can be interrupted at any point and returns a valid (if approximate) result. For transformer inference, the natural interruption point is at an intermediate layer. A well-calibrated confidence signal at that layer allows the scheduler to determine whether the intermediate output is sufficient---thereby spending far less than the full-pass budget on many tokens, while still finishing within deadline on all tokens.

\subsection{Contributions}

This paper makes the following specific contributions:

\begin{enumerate}[leftmargin=*]
    \item \textbf{KV-cached anytime scheduler:} A single-pass scheduler using a forward hook to capture both Layer-16 and full-pass logits simultaneously, eliminating the KV-cache desynchronization problem inherent in two-pass approaches.

    \item \textbf{Schedulability proof:} Formal measurement demonstrating $\text{P99\_TPOT} = 25.2$~ms under $D = 45$~ms ($U = 0.56$) with 0\% deadline misses across 240 TPOT samples on chat-template formatted prompts.

    \item \textbf{Exit-layer ablation:} Systematic comparison of exit layers L5--L20 against the oracle (L22), validating Layer~16 as the optimal early-exit point.

    \item \textbf{Per-length WCET profiling:} A per-sequence-length worst-case execution time table (200~runs/cell) used at runtime for conservative schedulability decisions, replacing a global constant.

    \item \textbf{EVT probabilistic WCET bounds:} Gumbel extreme value fits to 500 forward-pass samples per cell, establishing $P(\text{TPOT} > 45\,\text{ms}) < 10^{-8}$ for sequences $\leq 512$ tokens.

    \item \textbf{Real-time systems analysis suite:} Thermal stability profiling, Liu \& Layland multi-request capacity analysis, admission control policy derivation, and inter-token jitter characterization.
\end{enumerate}

\section{Background and Related Work}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Anytime Algorithms}

Anytime algorithms~\cite{zilberstein1996using,boddy1994deliberation} are computations that produce valid results at any point during execution, with quality monotonically improving over time. The scheduler monitors elapsed time and interrupts the computation when a deadline approaches, committing the best available result. This property is essential for hard real-time systems where missing a deadline is worse than returning a slightly lower-quality answer.

\subsection{Early Exit in Transformer Models}

Early exit in deep networks was proposed by Teerapittayanon et al.~\cite{teerapittayanon2016branchynet} and adapted to transformers in BERT~\cite{liu2020fastbert,xin2020deebert}, where intermediate classifier heads are attached at multiple layers and a sample exits once confidence exceeds a threshold. ElasticBERT~\cite{liu2021elasticbert} demonstrated jointly-trained multi-exit transformers that preserve accuracy at aggressive exit rates.

In LLM generation, Schuster et al.~\cite{schuster2022confident} introduced confident adaptive language modeling, conceptually similar to our two-pass approach. LayerSkip~\cite{elhoushi2024layerskip} demonstrates that later layers in TinyLlama carry substantially more predictive signal than early layers, consistent with our ablation results. Li et al.~\cite{li2023accelerating} study layer-skipping in decoder-only models.

\subsection{Real-Time Scheduling for ML Inference}

Real-time scheduling of neural network inference has been studied in embedded settings~\cite{bateni2020neuos,xiang2019pipelined}. These works focus on WCET analysis and preemption. Liu and Layland~\cite{liu1973scheduling} established the foundational utilization bound $U_{LL}(N) = N(2^{1/N}-1)$ for $N$ equal-rate periodic tasks under Rate-Monotonic Scheduling. Buttazzo~\cite{buttazzo2011hard} provides comprehensive treatment of sporadic task models and EDF/RMS schedulability theory. Our work applies these concepts directly to LLM token generation.

\subsection{Probabilistic WCET}

Measurement-based probabilistic timing analysis~\cite{cucu2012measurement} fits statistical distributions to execution time samples to bound tail latency at exceedance probabilities below $10^{-9}$. Bernat et al.~\cite{bernat2002wcet} pioneered applying Extreme Value Theory (EVT) distributions, particularly the Gumbel family, to WCET estimation. Davis and Cucu-Grosjean~\cite{davis2013quantifying} survey the state of the art. We apply Gumbel EVT to GPU forward-pass timing samples to bound the probability of a deadline miss.

\subsection{KV Cache Efficiency}

PagedAttention~\cite{kwon2023efficient} and FlashAttention~\cite{dao2022flashattention,dao2023flashattention2} are the primary techniques for reducing KV-cache memory and recomputation cost. We leverage FlashAttention implicitly (via \texttt{torch.nn.functional.\allowbreak scaled\_dot\_product\_attention} in PyTorch~2.4+) and rely on the $O(n_{\text{cache}})$ single-token pass to bound per-token latency independently of accumulated context length.

\section{System Design}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Hardware and Model}

\textbf{Hardware:} RunPod bare-metal instance, NVIDIA RTX~4000~Ada Generation (21~GB VRAM, 130~W TDP, Boost 2610~MHz, CUDA~12.4). Bare-metal is required for valid WCET measurements; VM/hypervisor jitter invalidates worst-case timing.

\smallskip\noindent\textbf{Model:} TinyLlama/TinyLlama-1.1B-Chat-v1.0~\cite{zhang2024tinyllama}---22 transformer layers (LlamaDecoder), hidden dimension 2048, 32 attention heads, vocabulary size 32{,}000. Chat-template formatted prompts are used throughout so that measured latencies reflect deployment-realistic context lengths ($\approx$95--145 tokens).

\smallskip\noindent\textbf{Framework:} PyTorch~2.4.1 + CUDA~12.4, HuggingFace Transformers~5.5.3.

\subsection{EarlyExitTinyLlama}

We implement \texttt{EarlyExitTinyLlama}, a wrapper around the HuggingFace TinyLlama model that replaces the monolithic \texttt{forward()} with explicit layer-by-layer execution:
\begin{equation}
\text{logits}, \_ = \texttt{model}(\text{ids},\, \text{exit\_layer}=L,\, \text{use\_cache}=\text{False})
\end{equation}
where $L \in \{1, \ldots, 22\}$. If \texttt{exit\_layer} is \texttt{None}, all 22 layers execute (full pass). RMSNorm is always applied at the exit point, rotary embeddings are computed once and shared across all layers, and no in-place model state mutation occurs.

\subsection{forward\_cached() --- KV-Cache Desynchronization Fix}

A critical problem in two-pass stateless inference is \textit{KV-cache desynchronization}: tokens committed via the L16 early exit never update layers~16--21's key-value states. On subsequent full-pass tokens, the attention computation in layers~16--21 accesses stale KV states, corrupting the output.

We solve this with \texttt{forward\_cached()}, which registers a forward hook on \texttt{self.\_m.layers[15]} (0-indexed) to capture the intermediate hidden state. The full 22-layer pass executes for every token, but the hook intercepts the intermediate activation and projects it through RMSNorm and the LM head to yield L16 logits. Both L16 and full-pass logits are derived from the same single forward call:
\begin{equation}
\ell_{16},\, \ell_{22},\, \text{kv}' = \texttt{forward\_cached}(\text{ids},\, \text{past\_kv})
\end{equation}
The exit decision is \textit{post-hoc}: after both logits are available, the scheduler selects which token to commit. All 22 layers' KV states are updated on every step, ensuring cache consistency regardless of which logit is committed.

\subsection{Stateless Dynamic Scheduler}

The stateless dynamic scheduler (\texttt{generate\_stateless\_anytime}) uses a linear threshold decay:
\begin{equation}
\theta_t = \theta_{\min} + (\theta_{\max} - \theta_{\min}) \cdot \frac{r - w}{D - w}
\label{eq:decay}
\end{equation}
where $r$ is the remaining budget after the L16 probe, $w = \text{WCET}_{\text{safe}}(\text{seq\_len})$, $\theta_{\max} = 0.8$, and $\theta_{\min} = 0.3$. When $r < w$, a forced early exit is taken. This scheduler is \textbf{not schedulable} at $D = 45$~ms for typical chat-template PubMedQA prompts (150--200 tokens), because the two-pass total (L16 probe $\approx$14--20~ms + full pass $\approx$19--24~ms) produces a tail that exceeds 45~ms.

\subsection{KV-Cached Anytime Scheduler}

The KV-cached scheduler (\texttt{generate\_anytime\_with\_kv}) uses a fixed confidence threshold at the midpoint of the decay range:
\begin{equation}
\theta_{\text{kv}} = \frac{\theta_{\max} + \theta_{\min}}{2} = 0.55
\label{eq:kv_thresh}
\end{equation}

Per-token decision (post-hoc, after \texttt{forward\_cached} completes):
\begin{algorithmic}[1]
\STATE $\ell_{16}, \ell_{22}, \text{kv}' \leftarrow \texttt{forward\_cached}(\text{ids}, \text{past\_kv})$
\STATE $c \leftarrow \max(\texttt{softmax}(\ell_{16}[-1]))$
\IF{$c \geq 0.55$}
    \STATE commit $\arg\max(\ell_{16}[-1])$ \quad\textit{// Early Exit}
\ELSE
    \STATE commit $\arg\max(\ell_{22}[-1])$ \quad\textit{// Full Pass}
\ENDIF
\end{algorithmic}

No forced-exit logic is required because the single-pass always completes within 18--26~ms, well under $D = 45$~ms. The fixed threshold is sufficient since latency is already bounded by the single-pass design, and the post-hoc decision requires no budget-awareness.

\subsection{WCET Table and Safety Margin}

WCET is profiled by running 200 forward passes at each of six sequence lengths (32, 64, 128, 256, 512, 1024 tokens) for each exit layer using CUDA event timing. The worst-case (maximum) observed latency is extracted and stored in \texttt{wcet\_results.json}. At runtime, both schedulers load this table and apply a $1.10\times$ safety factor:
\begin{equation}
\text{WCET}_{\text{safe}}(s) = \max_{i:\, s_i \geq s} \Bigl( 1.10 \times \text{WCET}_{\text{measured}}(s_i) \Bigr)
\label{eq:wcet_safe}
\end{equation}
The ceiling lookup (smallest profiled bin $\geq$ current seq\_len) ensures the bound is always conservative.

\subsection{Formal Schedulability Proof}

We treat each token generation as a real-time task $\tau_i$ with deadline $D = 45$~ms. Schedulability is defined as:
\begin{align}
\text{P99\_TPOT} &\leq D \;\Rightarrow\; \text{SCHEDULABLE} \nonumber \\
U &= \frac{\text{P99\_TPOT}}{D} < 1.0
\label{eq:sched}
\end{align}

Figure~\ref{fig:schedulability} shows the tail-latency CDFs for the baseline (standard full-pass autoregressive) and the KV-cached anytime scheduler across 10 chat-template clinical prompts $\times$ 25 tokens = 240 TPOT samples (TTFT excluded).

\section{Real-Time Systems Analysis}

\subsection{CPU Scheduling Overhead}

A key question for mixed CPU/GPU systems is whether the scheduler's decision logic introduces measurable CPU overhead on top of the GPU kernel. We measure wall-clock time (via \texttt{time.perf\_counter\_ns}) and GPU kernel time (via CUDA events) for 200 consecutive tokens on each scheduler, then compute the CPU overhead as $\Delta t = t_{\text{wall}} - t_{\text{GPU}}$.

\begin{figure*}[t]
    \centering
    \includegraphics[width=0.72\textwidth]{cpu_overhead.png}

\subsection{SCHED\_FIFO Comparison}

Linux real-time scheduling class \texttt{SCHED\_FIFO} (priority~99) eliminates OS preemption jitter that can inflate worst-case GPU launch latency. We attempted to elevate the process using \texttt{os.sched\_setscheduler(0, os.SCHED\_FIFO, os.sched\_param(99))}. This requires \texttt{CAP\_SYS\_NICE} (Linux capability bit~23). On our RunPod container, \texttt{CapEff = 0xa80425fb} (bit~23 not set), so elevation fails with \texttt{PermissionError} despite running as root.

This is a container isolation limitation, not a scheduler deficiency. On bare-metal Linux deployments, \texttt{SCHED\_FIFO} would reduce OS-induced WCET variability, potentially tightening the empirical WCET bounds by $1$--$3$~ms.

\subsection{Extreme Value Theory WCET Bounds}

Empirical WCET (sample maximum $\times 1.10$) over 200 runs provides a practical safety margin, but extrapolating to exceedance probabilities below $10^{-4}$ requires statistical modeling. We apply Extreme Value Theory (EVT)~\cite{bernat2002wcet,coles2001introduction}: fitting a Gumbel (Type~I extreme value) distribution to the top 20\% of 500 timing samples per (seq\_len, exit\_layer) cell.

\begin{figure*}[t]
    \centering
    \includegraphics[width=\textwidth]{evt_wcet_analysis.png}
    \caption{EVT WCET analysis. \textit{Left:} empirical $\times1.10$ and EVT bounds ($\varepsilon = 10^{-4}$, $10^{-6}$) vs.\ sequence length for Full Pass and L16. \textit{Center:} Gumbel QQ-plot for Full Pass at seq=128. \textit{Right:} summary table with EVT vs.\ empirical comparison.}
    \label{fig:evt}
\end{figure*}

The Gumbel distribution has CDF $F(t) = \exp\!\bigl(-\exp(-(t-\mu)/\sigma)\bigr)$, location $\mu$ and scale $\sigma$ fitted by maximum likelihood. The pWCET bound at exceedance probability $\varepsilon$ is $\text{ppf}(1-\varepsilon)$.

Table~\ref{tab:evt} presents EVT results for the Full Pass exit layer. The seq=1024 cell has EVT($10^{-6}$) = 45.23~ms---essentially at the deadline, confirming that long-context inference is the schedulability boundary.

\subsection{Formal Task Model and Capacity Analysis}

We formalize token generation as a sporadic task $\tau$: computation time $C = 19.44$~ms (P99 TPOT from benchmark), deadline $D = 45$~ms, minimum inter-arrival period $T = D$ (tight binding). Single-task utilization:
\begin{equation}
U = C/D = 19.44/45 = 0.432 < 1.0 \;\Rightarrow\; \text{SCHEDULABLE}
\end{equation}

\begin{figure*}[b]
    \centering
    \includegraphics[width=\textwidth]{task_model_analysis.png}
    \caption{Formal task model analysis. \textit{Left:} effective TPOT under $N$-way round-robin token scheduling (green = schedulable, red = exceeds deadline). \textit{Center:} Liu \& Layland RMS bound vs.\ actual utilization. \textit{Right:} maximum concurrent requests $N_{\max}$ vs.\ deadline $D$.}
    \label{fig:task_model}
\end{figure*}

For $N$ concurrent inference requests under token-level round-robin scheduling, each token sees an effective TPOT of $N \times C$. The Liu \& Layland bound~\cite{liu1973scheduling} for $N$ equal-period tasks is:
\begin{equation}
U_{LL}(N) = N\bigl(2^{1/N} - 1\bigr)
\end{equation}

Table~\ref{tab:task_model} shows the schedulability analysis. $N_{\max} = \lfloor D/C \rfloor = \lfloor 45/19.44 \rfloor = 2$.

The RMS bound is sufficient but not necessary; round-robin is not RMS, and the weaker condition $N \times C \leq D$ holds. At $N=3$, effective TPOT~=~58.32~ms~$> D$, so only two concurrent requests can be admitted under this token-level scheduling policy.

% ─────────────────────────────────────────────────────────────────────────────
\section{Discussion}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Why KV Caching is Essential for Schedulability}

The fundamental limitation of the stateless two-pass scheduler is that every token requires two sequential forward passes. For chat-template PubMedQA prompts (150--200~tokens), the L16 probe consumes 14--20~ms of a 45~ms budget. When confidence is low (most tokens), the full pass adds another 19--24~ms, for a combined mean TPOT of $\approx$39~ms. The tail (P99 = 48.3~ms) exceeds the deadline, and 16\% of tokens miss.

The KV-cached design eliminates this by running one pass per token. The hook-captured L16 logits add zero forward-pass overhead; the $O(n_{\text{cache}})$ attention means single-token latency is nearly context-independent (18--26~ms observed from token~1 to token~25). The maximum observed TPOT across 240 samples is 26.2~ms---well below the minimum achievable two-pass latency.

\subsection{Anytime Property and Quality Tradeoff}

The early-exit rate in the KV-cached scheduler is 4.7\% across 30 queries, meaning 95.3\% of tokens use the full-pass logits. This low early-exit rate reflects the combined effect of low overall L16 agreement (32\%) and the fixed 0.55 threshold. The scheduler correctly falls through to the full-pass logits in most cases, preserving output quality.

This low exit rate should not be interpreted as inefficiency. The scheduler's primary function is to guarantee schedulability (zero missed deadlines at $D = 45$~ms), not to maximize early exits. The early-exit path provides an additional quality-vs-speed knob: raising the threshold allows more early exits when acceptable, without changing the WCET guarantee.

\subsection{WCET Assumptions and Validity}

Three analyses validate the static WCET assumption:
\begin{enumerate}[leftmargin=*]
    \item \textbf{CPU overhead} ($<0.025$~ms, $<0.2\%$): negligible, confirming GPU kernel time dominates.
    \item \textbf{Thermal drift} ($-0.86$~ms over 500 tokens): stable; the RTX~4000~Ada reaches steady-state before the timed measurement window.
    \item \textbf{EVT bounds}: $P(\text{TPOT} > 45\,\text{ms}) < 10^{-8}$ for seq~$\leq$~512, with $1.10\times$ empirical margin remaining conservative relative to the Gumbel fit for most lengths.
\end{enumerate}

The one concern is the seq=32 EVT($10^{-6}$) bound (38.1~ms) exceeding the empirical $\times1.10$ bound (26.4~ms). This reflects high relative jitter at short sequences, where GPU scheduling spikes are large relative to the $\approx$18~ms mean. In practice, PubMedQA prompts are $\geq$95 tokens, so this cell does not arise at runtime.

\subsection{Limitations and Future Work}

\textbf{Model size:} TinyLlama-1.1B is the smallest production-quality LLM available. Larger models (7B, 13B parameters) will have substantially higher per-token latency. The framework scales to larger models; the WCET table and exit layer may need re-profiling and adjustment.

\textbf{SCHED\_FIFO:} Container isolation prevents testing under \texttt{SCHED\_FIFO}. On bare-metal deployments, real-time priority would reduce OS-induced WCET variability by 1--3~ms, tightening the empirical bounds.

\textbf{Joint training:} Our early exit uses the shared LM head with RMSNorm at Layer~16. A jointly-trained exit head (lightweight MLP) could improve L16 agreement and increase the early-exit rate beyond 4.7\%.

\textbf{Multi-request scaling:} The $N_{\max} = 2$ round-robin capacity is modest. Batched inference with hardware-level concurrency (tensor cores operating on multiple requests in parallel) could raise this substantially, but requires re-profiling the WCET table under load.

% ─────────────────────────────────────────────────────────────────────────────
\section{Conclusion}
% ─────────────────────────────────────────────────────────────────────────────

We presented a KV-cached anytime algorithm for LLM token generation that guarantees hard deadline compliance by design. The core insight is that the KV-cache desynchronization problem inherent in two-pass stateless schedulers is eliminated by a single \texttt{forward\_cached()} call that captures Layer-16 intermediate activations via a forward hook while running all 22 layers. This design achieves $O(n_{\text{cache}})$ per-token attention, reducing latency variance to $<2$~ms within any single query.

Formal schedulability analysis on a bare-metal RTX~4000~Ada GPU demonstrates P99~TPOT~=~25.2~ms against $D=45$~ms ($U=0.56$), with 0\% deadline misses on 10 chat-template clinical prompts $\times$~25 generated tokens. A 30-query PubMedQA benchmark confirms 0\% deadline misses at 51.2~tok/s.

The expanded real-time analysis suite provides additional formal guarantees: EVT Gumbel fits establish $P(\text{miss}) < 10^{-8}$ for sequences $\leq512$~tokens; thermal profiling confirms WCET drift of only $-4.0\%$ over 500 consecutive tokens; and Liu \& Layland analysis derives $N_{\max}=2$ concurrent schedulable requests under round-robin token scheduling. These results establish that predictive early-exit mechanisms, when paired with KV-cached single-pass inference and rigorous real-time analysis, can enforce hard real-time constraints on LLM token generation without modifying the underlying model weights.
